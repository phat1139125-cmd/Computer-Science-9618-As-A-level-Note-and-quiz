TOPIC 01 · §9.1
Abstraction & Decomposition
COMPUTATIONAL THINKING SKILLS
Abstraction
  • Filter out unnecessary information
  • Only essential information is included
  • Simplifies the solution — easier to implement
  • System tailored to needs of user
Decomposition
  • Breaking a complex problem into smaller sub-problems
  • Sub-problems easier to program, test and maintain
  • Leads to modular design
  • Sub-problems can be given to different teams
  • Solved separately and combined
⚡ EXAM  Abstraction = remove unnecessary detail. Decomposition = break into smaller parts. Both make problems easier to solve and programs easier to test and maintain.
TOPIC 02 · §9.2
Algorithms & Stepwise Refinement
ALGORITHM DEFINITION · STEPWISE REFINEMENT · PSEUDOCODE
ALGORITHM

A sequence of defined steps that describe how to solve a problem.

STEPWISE REFINEMENT

Process of developing a modular design by repeatedly splitting a problem into sub-tasks until each sub-task is a single programmable statement.

Pseudocode Reference — Key Constructs
// Variables & Constants DECLARE variable_name : DATATYPE CONSTANT CONST_NAME : value // Input / Output INPUT variable_name OUTPUT variable_name, "string" // IF statement IF condition THEN statements ELSE statements ENDIF // CASE statement CASE OF variable value1 : statement value2 : statement OTHERWISE : statement ENDCASE // FOR loop (count-controlled) FOR i ← 1 TO 10 statements NEXT i // WHILE loop (pre-condition) WHILE condition statements ENDWHILE // REPEAT loop (post-condition) REPEAT statements UNTIL condition
FOR loop — use when
  • Number of iterations is KNOWN in advance
  • Count-controlled repetition
WHILE loop — use when
  • Number of iterations NOT known
  • Condition checked BEFORE loop body
  • Loop may not execute if condition false from start
REPEAT loop — use when
  • Number of iterations NOT known
  • Condition checked AFTER loop body
  • Loop always executes AT LEAST ONCE
TOPIC 03 · §9.3
Linear & Binary Search
HOW THEY WORK · COMPARISON · PRECONDITIONS
FEATURELINEAR SEARCHBINARY SEARCH
PreconditionNone — works on unsorted dataData MUST be sorted (ascending or descending)
MethodChecks each element sequentially from startFinds mid-point, discards half, repeats
ComparisonsUsually more comparisonsFewer comparisons (logarithmic)
Time complexityO(n) — linearO(log n) — logarithmic
Best forSmall/unsorted listsLarge sorted lists
Binary Search Process

Find the middle index of the list

Check if middle value equals target — if yes, found!

If target < middle value → discard upper half

If target > middle value → discard lower half

Repeat until found OR only one element remains and it doesn't match

// Binary Search pseudocode DECLARE First, Last, Mid : INTEGER First ← 0 Last ← Length - 1 Found ← FALSE WHILE First <= Last AND NOT Found Mid ← (First + Last) DIV 2 IF List[Mid] = Target THEN Found ← TRUE ELSE IF List[Mid] > Target THEN Last ← Mid - 1 ELSE First ← Mid + 1 ENDIF ENDWHILE
TOPIC 04 · §9.3
Bubble Sort & Insertion Sort
HOW EACH WORKS · PSEUDOCODE
Bubble Sort
  • Repeatedly compares adjacent pairs
  • Swaps if in wrong order
  • Largest values "bubble" to end each pass
  • Outer loop: runs n times
  • Inner loop: each pass leaves out one more element at end
  • O(n²) — quadratic time complexity
Insertion Sort
  • Builds sorted portion one element at a time
  • Compares current element with those before it
  • Inserts element into correct position in sorted portion
  • Efficient for nearly-sorted data
  • O(n²) worst case, O(n) best case
// Bubble Sort pseudocode FOR i ← 1 TO Length - 1 FOR j ← 0 TO Length - 1 - i IF List[j] > List[j+1] THEN Temp ← List[j] List[j] ← List[j+1] List[j+1] ← Temp ENDIF NEXT j NEXT i
Factors affecting sort performance
  • Initial order of data
  • Number of data items to be sorted
  • Efficiency of the sorting algorithm
TOPIC 05 · §9.3
Big O Notation
TIME COMPLEXITY · SPACE COMPLEXITY
BIG O NOTATION

Used to indicate the time or space complexity of an algorithm — how performance scales with input size.

ALGORITHMBIG OMEANING
Linear searchO(n)Time increases linearly with number of items
Binary searchO(log n)Time increases logarithmically — much slower growth
Bubble sortO(n²)Time increases as square of items — slow for large n
Insertion sortO(n²)Worst case quadratic; best case O(n) for nearly-sorted
⚡ O(log n) EXPLAINED  "The time taken goes up linearly as the number of items rises exponentially." So doubling the items only adds 1 more comparison for binary search — much more efficient than linear search for large lists.

QUESTION 03
Describe how a binary search works on the list: [2, 5, 8, 12, 16, 23, 38, 56, 72, 91] to find the value 23. [4]

MARK SCHEME

  • Find mid-point: index 4 (value 16) (1)
  • 23 > 16 → discard lower half; new list [23, 38, 56, 72, 91] (1)
  • Find new mid-point: index 7 (value 56) (1)
  • 23 < 56 → discard upper half; new list [23, 38]; mid = 23 → found (1)
Examiner: Show each step including mid calculation and which half is discarded.
◆ STANDARD
QUESTION 04
Compare linear search and binary search. Give two differences. [4]

MARK SCHEME (any 2 × 2)

  • Linear: no precondition / Binary: data must be sorted (1) — binary search is faster on sorted lists (1)
  • Linear: O(n) / Binary: O(log n) (1) — binary search scales better for large datasets (1)
  • Linear: checks each element in sequence / Binary: halves the search space each iteration (1)
◆ STANDARD
QUESTION 05
Justify whether a FOR, WHILE or REPEAT loop is most suitable when: (a) reading exactly 10 numbers from the user, (b) reading numbers until a negative value is entered. [4]

MARK SCHEME

  • (a) FOR loop (1) — number of iterations (10) is known in advance (1)
  • (b) REPEAT or WHILE loop (1) — number of iterations not known; depends on when user enters negative value (1)
Examiner: Must justify the choice — name alone = 0.
★ CHALLENGE
QUESTION 06
Trace through a bubble sort on the list [5, 1, 4, 2] and show the list after each pass. [3]

MARK SCHEME

  • Pass 1: Compare 5,1→swap; 5,4→swap; 5,2→swap → [1, 4, 2, 5] (1)
  • Pass 2: Compare 1,4→no swap; 4,2→swap → [1, 2, 4, 5] (1)
  • Pass 3: Compare 1,2→no swap → [1, 2, 4, 5] — sorted (1)
★ CHALLENGE
QUESTION 07
Explain what O(log n) means and why binary search has this complexity. [3]

MARK SCHEME

  • O(log n) means time taken increases logarithmically with the number of items (1)
  • Time goes up linearly as number of items rises exponentially (1)
  • Binary search halves the search space each step — so doubling the list only adds one more comparison (1)
