TOPIC 01 · §20.1
Programming Paradigms
WHAT IS A PARADIGM · FOUR TYPES
PROGRAMMING PARADIGM
  • A set of programming concepts
  • Defines the structure and capability of a programming language
  • Different paradigms solve problems in different ways
PARADIGMKEY FEATUREEXAMPLES
Low-LevelUses processor instruction set directly; uses addressing modesAssembly language
Imperative (Procedural)Explicit sequence of commands; uses variables + assignment + iterationPython, Pascal, C
Object-OrientedUses classes, inheritance, encapsulation, polymorphismJava, Python, C++
DeclarativeSpecifies WHAT to do, not HOW; uses facts, rules and queriesSQL, Prolog, HTML
TOPIC 02 · §20.1
Low-Level & Imperative Paradigms
LOW-LEVEL · ADDRESSING MODES · IMPERATIVE/PROCEDURAL
Low-Level Programming
  • Uses the instruction set of a specific processor
  • Uses different addressing modes:
  • → Immediate: value given directly in instruction
  • → Direct: address of data given
  • → Indirect: address of address given
  • → Indexed: base address + index register
  • → Relative: offset from current PC value
Imperative (Procedural) Programming
  • Uses variables changed via assignment statements
  • Relies on iterative/repetitive methods
  • Explicit sequence of commands — each line changes program state
  • Programmer specifies exactly HOW the task is done
  • Uses procedures, functions and structured programming
TOPIC 03 · §20.1
Object-Oriented Programming (OOP)
CLASS · OBJECT · INHERITANCE · POLYMORPHISM · ENCAPSULATION
OOP CORE CONCEPTS
  • Class: template/blueprint — defines attributes and methods
  • Object: an instance of a class — allocated memory space when created
  • Inheritance: methods and properties of one class reused in a derived class
  • Polymorphism: methods redefined (take different behaviours) in derived classes
  • Encapsulation: properties and methods grouped in a class — sensitive data hidden
Class vs Object
FEATURECLASSOBJECT
DefinitionTemplate from which objects are createdAn instance of a class
MemoryNOT allocated memory when definedAllocated memory when created
How manyDefined only onceMany objects created from one class
Can manipulate?No — not available in memoryYes — exists in memory
InheritanceClasses can use inheritanceObjects cannot
// Class definition in pseudocode CLASS Student PRIVATE StudentID : INTEGER PRIVATE Name : STRING PRIVATE Grade : CHAR // Constructor PUBLIC PROCEDURE NEW(id : INTEGER, n : STRING, g : CHAR) StudentID ← id Name ← n Grade ← g ENDPROCEDURE // Getter PUBLIC FUNCTION GetName() RETURNS STRING RETURN Name ENDFUNCTION // Setter PUBLIC PROCEDURE SetGrade(g : CHAR) Grade ← g ENDPROCEDURE ENDCLASS // Creating an object (instance) DECLARE S1 : Student S1 ← NEW Student(101, "Ahmed", 'A') OUTPUT S1.GetName() // Output: Ahmed
Inheritance
// Derived class inherits from base class CLASS PostGradStudent INHERITS Student PRIVATE ThesisTitle : STRING PUBLIC PROCEDURE NEW(id : INTEGER, n : STRING, g : CHAR, t : STRING) CALL SUPER.NEW(id, n, g) // call parent constructor ThesisTitle ← t ENDPROCEDURE ENDCLASS
TOPIC 04 · §20.1
OOP Terminology
ATTRIBUTES · METHODS · GETTER · SETTER · CONSTRUCTOR · INSTANCE
Properties / Attributes
  • Data items or data types defined in a class
  • Private attributes enforce encapsulation
  • Only accessible using class's own methods
Methods
  • Modules (functions/procedures) in a class
  • Implement behaviours that act on attributes
  • Can be public (accessible outside) or private (internal only)
Getter
  • A method that RETURNS the value of a private attribute
  • Provides read access without exposing attribute directly
  • Naming: GetAttributeName()
Setter
  • A method that UPDATES/SETS value of a private attribute
  • Can include validation before setting
  • Naming: SetAttributeName(value)
Constructor
  • Special method used to CREATE instances of objects
  • Called automatically when object is created
  • Initialises attributes of new object
  • Named NEW or __init__ depending on language
Instance
  • An occurrence/creation of an object from a class
  • Each instance has its own copy of attributes
  • Multiple instances can be created from one class
⚡ OOP EXAM PATTERNS  "State what is meant by encapsulation" = grouping attributes and methods inside a class, hiding sensitive data. "Explain inheritance" = methods/properties of parent class available to derived class — avoids code duplication. "What is polymorphism" = methods redefined for derived classes to take different behaviours.
TOPIC 05 · §20.1
Declarative Programming
WHAT IT IS · FACTS · RULES · QUERIES · PROLOG STYLE
DECLARATIVE PROGRAMMING
  • Instructs a program on WHAT needs to be done — not HOW to do it
  • Specifies desired result rather than method of acquiring it
  • Uses facts, rules and queries to satisfy goals
  • Can be logical (set of logical relations) or functional (applying functions to arguments)
Facts
  • Statements of truth about the world
  • e.g. parent(tom, bob).
  • States that tom is parent of bob
Rules
  • Define relationships based on facts
  • e.g. grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
  • X is grandparent of Z if X is parent of Y AND Y is parent of Z
Queries
  • Questions asked about facts and rules
  • e.g. ?- grandparent(tom, ann).
  • System answers yes/no or finds matching values
// Declarative example (Prolog-style) // Facts parent(tom, bob). parent(tom, liz). parent(bob, ann). // Rule grandparent(X, Z) :- parent(X, Y), parent(Y, Z). // Query ?- grandparent(tom, ann). // returns: yes ?- grandparent(tom, Who). // returns: Who = ann
⚡ DECLARATIVE vs IMPERATIVE  Imperative: tells computer HOW to do it (step by step). Declarative: tells computer WHAT result is wanted (system works out how). SQL is declarative — SELECT * FROM table WHERE condition tells WHAT, not HOW to search.
TOPIC 06 · §20.2
Exception Handling
WHAT IS AN EXCEPTION · EXCEPTION HANDLING ROUTINE · TRY/EXCEPT
EXCEPTION
  • An unexpected event that occurs during execution of a program
  • Causes the program to halt execution if not handled
  • Examples: end of file, division by zero, invalid input, hardware failure
  • These are runtime errors
EXCEPTION HANDLING ROUTINE
  • Responds to unexpected events while program is running
  • Prevents programs from halting unexpectedly
  • Traps runtime errors — executes alternative code
  • Produces meaningful error messages
When to Use Exception Handling
  • Division by zero — user enters 0 as divisor
  • File not found — file path incorrect
  • End of file reached unexpectedly
  • Invalid data type entered
  • Network connection failure
  • Any runtime error that can be anticipated
// Exception handling structure (pseudocode) TRY // Code that might cause an exception INPUT number result ← 100 / number OUTPUT result EXCEPT // Code executed if exception occurs OUTPUT "Error: division by zero or invalid input" ENDTRY
# Python exception handling try: number = int(input("Enter a number: ")) result = 100 / number print(result) except ZeroDivisionError: print("Error: cannot divide by zero") except ValueError: print("Error: please enter a valid number") except: print("An unexpected error occurred")
⚡ EXCEPTION HANDLING EXAM  "Explain what exception handling does" = prevents program halting unexpectedly when a runtime error occurs; traps the error and executes alternative code; produces meaningful error message. TRY block = normal code. EXCEPT block = runs only if exception occurs.

QUESTION 03
Explain the terms encapsulation, inheritance and polymorphism in OOP. [6]

MARK SCHEME (2 marks each)

  • Encapsulation: process of putting properties and methods inside a class as a single unit (1) — ensures sensitive data is hidden/only accessible through class's own methods (1)
  • Inheritance: methods and properties of one class made available to a derived/child class (1) — allows code reuse without rewriting (1)
  • Polymorphism: allows methods to be redefined in derived classes (1) — same method name but different behaviour depending on the class (1)

QUESTION 04
Explain the purpose of getter and setter methods in OOP. Why are they used with private attributes? [4]

MARK SCHEME

  • Getter: method that returns the value of a private attribute (1)
  • Setter: method that updates/sets the value of a private attribute (1)
  • Used because private attributes cannot be accessed directly from outside the class (1)
  • Setters can include validation before updating the attribute — protects data integrity (1)

  • Imperative: explicit sequence of commands telling computer HOW to do the task step by step (1)

QUESTION 06
Write pseudocode for a class called Car with private attributes Make and Speed, a constructor, a getter for Make and a setter for Speed. [6]

MARK SCHEME

  • CLASS Car ... ENDCLASS (1)
  • PRIVATE Make : STRING / PRIVATE Speed : INTEGER (1)
  • Constructor: PUBLIC PROCEDURE NEW(m : STRING, s : INTEGER) / Make←m / Speed←s / ENDPROCEDURE (1)
  • Getter: PUBLIC FUNCTION GetMake() RETURNS STRING / RETURN Make / ENDFUNCTION (1)
  • Setter: PUBLIC PROCEDURE SetSpeed(s : INTEGER) / Speed←s / ENDPROCEDURE (1)
  • Correct use of PUBLIC/PRIVATE access modifiers throughout (1)
◆ STANDARD
QUESTION 07
Explain what an exception is and describe how exception handling prevents a program from crashing. [4]

MARK SCHEME

  • Exception: an unexpected event that occurs during program execution (1)
  • Without handling: exception causes the program to halt unexpectedly (1)
  • Exception handling: code placed in TRY block — if exception occurs, EXCEPT block executes instead (1)
  • Produces meaningful error message — program continues or terminates gracefully (1)

QUESTION 08
Write pseudocode to define a class Animal with a private attribute Name, a constructor and a method Speak that outputs "..." Then write a derived class Dog that inherits Animal and overrides Speak to output "Woof!". [6]

MARK SCHEME

  • CLASS Animal / PRIVATE Name : STRING (1)
  • PUBLIC PROCEDURE NEW(n:STRING) / Name←n / ENDPROCEDURE (1)
  • PUBLIC PROCEDURE Speak() / OUTPUT "..." / ENDPROCEDURE / ENDCLASS (1)
  • CLASS Dog INHERITS Animal (1)
  • PUBLIC PROCEDURE Speak() / OUTPUT "Woof!" / ENDPROCEDURE (1) — overrides parent method (polymorphism)
  • ENDCLASS / correct structure throughout (1)
Examiner: The Dog's Speak() overriding Animal's Speak() demonstrates polymorphism.
