TOPIC 01 · §4.1
Von Neumann Architecture & Registers
STORED PROGRAM CONCEPT · SPECIAL PURPOSE REGISTERS
STORED PROGRAM CONCEPT

Instructions and data are stored in the same memory space (main memory). The CPU fetches and executes instructions stored in memory one at a time.

Von Neumann Components
Buses
  • Address bus — carries memory addresses
  • Data bus — carries data between components
  • Control bus — carries control signals
CPU
  • CU — Control Unit
  • ALU — Arithmetic & Logic Unit
  • IAS — Immediate Access Store
  • System Clock
Registers
  • PC, MAR, MDR, CIR, ACC
  • Index Register (IX)
  • Status Register
Special Purpose Registers
REGISTERABBREVIATIONPURPOSE
Program CounterPCHolds address of NEXT instruction to be fetched. Incremented each cycle.
Memory Address RegisterMARHolds address of memory location currently being read from or written to.
Memory Data RegisterMDRHolds data fetched from address in MAR. Data copied to CIR.
Current Instruction RegisterCIRHolds instruction currently being decoded and executed.
Index RegisterIXStores a value added to an address to give another address (indexed addressing).
Status RegisterSRStores flags from results of operations and interrupt flags.
AccumulatorACCGeneral purpose register — holds results of arithmetic/logic operations.
FEATUREGENERAL PURPOSE REGISTERSSPECIAL PURPOSE REGISTERS
UseHold temporary data, used for any purposeHold status/specific data
AccessCan be used by most instructionsOnly used by certain instructions
TOPIC 02 · §4.1
CPU Components
CU · ALU · SYSTEM CLOCK · IAS · BUSES
Control Unit (CU)
  • Synchronises actions of other CPU components (based on system clock)
  • Sends/receives control signals along control bus
  • Manages execution of instructions
  • Decodes instruction opcode during F-E cycle
  • Controls communication between CPU components
  • Signal types: interrupt, timing, read & write
System Clock
  • Synchronises computer operations by creating time signals
  • Allows operations to be processed in correct order
  • Keeps track of date and time
  • Each tick = one clock cycle
IAS — Immediate Access Store
  • Holds all data/programs currently in use
  • Volatile memory
  • Fast access times
  • Also called main memory / RAM
Buses
  • Address bus: carries address where data is going to/from
  • Data bus: carries data between components
  • Control bus: CU sends timing, read/write, interrupt signals
TOPIC 03 · §4.1
Fetch-Execute Cycle
STAGES · REGISTER TRANSFER NOTATION ★
Stages of the F-E Cycle

PC stores address of next instruction to fetch

Address copied from PC to MAR via address bus

Instruction copied from main memory to MDR via data bus

Instruction copied from MDR to CIR

CIR instruction decoded by CU (into opcode and operand)

Processor executes instruction

Address in PC incremented to point to next instruction

Register Transfer Notation ★ (Exam Favourite)
NOTATIONMEANING
MAR ← [PC]Contents of PC loaded to MAR (fetch step 2)
MDR ← [[MAR]]Data at address held in MAR copied to MDR
CIR ← [MDR]Contents of MDR copied to CIR
[PC] ← [PC] + 1Address in PC is incremented
⚡ RTN EXAM  Square brackets [ ] mean "contents of". Double brackets [[ ]] mean "data at the address stored in". Always use arrows ← not = in RTN.
TOPIC 04 · §4.1
Interrupts
PURPOSE · CAUSES · HANDLING PROCESS
PURPOSE OF AN INTERRUPT

To send a signal from a device/process to the processor, seeking attention of the processor so it can handle the request.

Software Interrupt Causes
  • Division by zero
  • Attempt to access invalid memory location
  • Array index out of bounds
  • Stack overflow
  • Buffer overflow
Hardware Interrupt Causes
  • Printer out of paper
  • Keyboard key press
  • Power failure
  • I/O device signals completion
Interrupt Handling Process

Interrupt flag raised in interrupt register

Register checked at start/end of each F-E cycle

Type and source of interrupt identified

Priority checked — if lower than current process, F-E cycle continues

If higher priority: contents of registers saved to a stack

Address of appropriate ISR loaded to PC and executed

After ISR finishes: check for further interrupts

Otherwise: restore registers from stack and continue previous process

⚡ INTERRUPT EXAM PATTERN  Key marks: "flag raised", "checked at end of cycle", "registers saved to stack", "ISR address loaded to PC", "registers restored from stack". The STACK is critical — always mention it.
TOPIC 05 · §4.1
CPU Performance Factors
CORES · CLOCK SPEED · CACHE · BUS WIDTH · RAM
FACTORHOW IT IMPROVES PERFORMANCELIMITATION
Number of CoresEach core processes one instruction per clock pulse. More cores → more instructions simultaneously → faster tasksSoftware may not be designed for multiple cores — one core may be idle
Clock SpeedFaster clock = more instructions per second. Each instruction executed on one clock pulse.Heat generation, battery consumption
Cache MemoryStores frequently used instructions near CPU. Prevents CPU waiting for RAM. More cache = more instructions available fast.Expensive; limited size
Bus WidthWider bus = more data transferred per cycle. More efficient data movement.Must match other component widths
RAM QuantityMore applications in main memory simultaneously. Saves/decreases disk access times.Virtual memory overhead if exceeded
TOPIC 06 · §4.2
Assembly Language & Two-Pass Assembler
INSTRUCTION GROUPS · TWO-PASS ASSEMBLER
Instruction Groups
  • Data movement — moves data between addresses/locations
  • Input/output — takes input, outputs character
  • Arithmetic operations — addition or subtraction
  • Unconditional/conditional — jump to another instruction
  • Compare — compares result to another value
Two-Pass Assembler — First Pass
  • Creates a symbol table
  • Reads assembly language one line at a time
  • Adds symbolic addresses/labels to symbol table
  • Removes comments and white space
  • Checks opcode is in instruction set
Two-Pass Assembler — Second Pass
  • Generates object/machine code
  • Reads assembly program one line at a time
  • Replaces symbolic addresses with actual addresses from symbol table
Key Assembly Instructions (9618 Instruction Set)
OPCODEOPERATION
LDM #nImmediate addressing — load number n to ACC
LDD <address>Direct — load contents of given address to ACC
LDI <address>Indirect — address at given address loaded to ACC
LDX <address>Indexed — address + IX register content, load to ACC
STO <address>Store contents of ACC to given address
ADD / SUBAdd/subtract contents of address from ACC
JMP <address>Unconditional jump to given address
CMP / JPE / JPNCompare ACC; jump if equal (JPE) or not equal (JPN)
IN / OUTInput character to ACC / output character from ACC
ENDReturn control to operating system
TOPIC 07 · §4.2
Addressing Modes
IMMEDIATE · DIRECT · INDIRECT · INDEXED · RELATIVE
MODEOPERAND CONTAINSWHAT IS LOADED TO ACC
ImmediateThe data itself (#n)The data value directly
DirectMemory address of dataData at the given address
IndirectAddress that stores the actual addressData at address stored at operand address
IndexedBase address (+ IX register content)Data at (operand address + IX)
RelativeOffset from current instructionAllows relocatable code
⚡ ADDRESSING TRICK  All modes load contents of the calculated address into ACC. The difference is HOW that address is calculated. Immediate = data is the operand itself (fastest). Indirect = two memory lookups needed (slowest).
TOPIC 08 · §4.3
Bit Manipulation
BINARY SHIFTS · BIT MASKING
OPERATIONWHAT HAPPENSEFFECT
Logical Left ShiftBits moved left, 0s fill from rightMultiplies by 2 per shift
Logical Right ShiftBits moved right, 0s fill from leftDivides by 2 per shift
Arithmetic ShiftSign bit preserved; 1s fill vacant positionsPreserves sign for signed numbers
Cyclic ShiftBits shifted out of one end appear at other endNo bits lost
Bit Masking
AND Masking
  • Used to CHECK if a bit has been set
  • AND with 1 = preserves bit; AND with 0 = clears bit
  • Use to read specific bits
OR Masking
  • Used to SET a bit to 1
  • OR with 1 = sets bit to 1; OR with 0 = no change
XOR Masking
  • Used to TOGGLE/CLEAR a bit
  • XOR with 1 = toggles bit; XOR with 0 = no change

QUESTION 04 · Describe
Describe how an interrupt is handled by the processor. [5]

MARK SCHEME (any 5)

  • Interrupt flag raised in interrupt register (1)
  • Checked at start/end of F-E cycle (1)
  • Priority of interrupt checked against current process (1)
  • If higher priority: contents of registers saved to a stack (1)
  • Address of ISR loaded to PC and executed (1)
  • After ISR: registers restored from stack / continue previous process (1)
Examiner: Key marks: "flag", "checked at end of cycle", "saved to stack", "ISR address to PC", "restored from stack". Always mention the STACK.
◆ STANDARD
QUESTION 05 · Explain
Explain how increasing the number of processor cores can improve performance. Give one reason why this may NOT always increase performance. [3]

MARK SCHEME

  • Each core can process one instruction per clock pulse (1)
  • More cores allow multiple sequences of instructions to execute simultaneously (1)
  • [Limitation] Software may not be designed for multiple cores — one or more cores may remain idle (1)
◆ STANDARD
QUESTION 06 · Explain
Explain the difference between direct and indirect addressing modes. [4]

MARK SCHEME

  • Direct: operand holds the memory address of the data (1)
  • Direct: data at that address is loaded into ACC (1)
  • Indirect: operand holds an address that itself stores the actual address of the data (1)
  • Indirect: data at the address stored at operand address is loaded to ACC (two memory accesses required) (1)

MARK SCHEME

  • Shift left 2: 10110110 → 11011000 (1)
  • Bits shifted out (10) are lost; 0s fill from right (1)
Examiner: Logical shift: vacated positions filled with 0s from right. Bits shifted out are discarded. Show working.

QUESTION 08 · Explain
Explain two causes of software interrupts. [4]

MARK SCHEME (any 2 × 2)

  • Division by zero (1) — program attempts arithmetic operation that is undefined (1)
  • Access to invalid memory location (1) — program tries to read/write outside its allocated memory (1)
  • Array index out of bounds (1) — program accesses index beyond array size (1)
  • Stack overflow (1) — recursion or too many function calls exceed available stack space (1)
