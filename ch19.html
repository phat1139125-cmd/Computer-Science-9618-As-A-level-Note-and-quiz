TOPIC 01 · §19.2
Recursion
DEFINITION · BASE CASE · GENERAL CASE · WINDING/UNWINDING
RECURSION
  • A process using a function/procedure that calls itself
  • Must have a base case (stopping condition) — prevents infinite recursion
  • Must have a general case — calls itself recursively, moves toward base case
Winding Phase
  • Statements AFTER the recursive call not executed
  • Each recursive call pushed onto the stack
  • Continues until base case reached
Unwinding Phase
  • Occurs once base case is reached
  • Each call is popped from stack in reverse order
  • Deferred statements execute as stack unwinds
Benefits of Recursion
  • Fewer programming statements needed
  • Simpler solutions to complex problems
  • Code more elegant and readable
Drawbacks of Recursion
  • Repetitive — demanding use of stack
  • Stack overflow can occur
  • Infinite recursion possible if base case wrong
  • More storage space required
// Recursive factorial example FUNCTION Factorial(n : INTEGER) RETURNS INTEGER IF n = 0 THEN // base case RETURN 1 ELSE RETURN n * Factorial(n - 1) // general case ENDIF ENDFUNCTION
⚡ RECURSION EXAM  Always identify: (1) base case — what stops the recursion? (2) general case — how does it call itself and move toward base case? Stack used to store return addresses/local variables each call.
TOPIC 02 · §19.2
Stacks & Recursion
WHY STACKS · COMPILER TRANSLATION · UNWINDING
WHY STACKS ARE EFFECTIVE FOR RECURSION
  • Stacks have LIFO structure — matches reverse order needed for unwinding
  • Each recursive call is pushed to stack — popped as function ends
  • Enables backtracking/unwinding to maintain required order
COMPILER TRANSLATION OF RECURSION

Compiler must produce object code to:

  • Push return addresses/values of local variables onto stack with each recursive call
  • Pop return addresses/values of local variables off stack after base case is reached
TOPIC 03 · §19.1
Binary Trees
STRUCTURE · TRAVERSALS · INSERT · FIND
BINARY TREE
  • Each node has at most two children (left and right)
  • Left child value < parent value
  • Right child value > parent value
  • Root node at top — no parent
  • Leaf nodes at bottom — no children
Tree Traversals
In-Order (LNR)
  • Visit Left subtree
  • Visit Node
  • Visit Right subtree
  • Result: sorted/ascending order
Pre-Order (NLR)
  • Visit Node first
  • Visit Left subtree
  • Visit Right subtree
  • Used to copy/recreate tree
Post-Order (LRN)
  • Visit Left subtree
  • Visit Right subtree
  • Visit Node last
  • Used to delete tree / evaluate expressions
// In-order traversal (recursive) PROCEDURE InOrder(node) IF node <> NULL THEN InOrder(node.Left) // visit left OUTPUT node.Data // visit node InOrder(node.Right) // visit right ENDIF ENDPROCEDURE // Insert into binary search tree PROCEDURE Insert(node, value) IF value < node.Data THEN IF node.Left = NULL THEN node.Left ← NewNode(value) ELSE Insert(node.Left, value) ENDIF ELSE IF node.Right = NULL THEN node.Right ← NewNode(value) ELSE Insert(node.Right, value) ENDIF ENDIF ENDPROCEDURE
⚡ TRAVERSAL MNEMONIC  In-Order = LNR → gives SORTED output. Pre-Order = NLR → Node first. Post-Order = LRN → Node last. The letter order tells you when the Node is visited: Pre=first, In=middle, Post=last.
TOPIC 04 · §19.1
Graphs as ADTs
STRUCTURE · KEY FEATURES · WHEN TO USE
GRAPH AS AN ADT
  • Collection of nodes (vertices) and edges
  • Edges can be directed (one-way) or undirected (two-way)
  • Edges can be weighted (have a cost/distance value)
  • Can be cyclic (contains cycles) or acyclic (no cycles)
  • Unlike trees — no hierarchy, any node can connect to any other
Key Features of a Graph
  • Nodes represent entities (cities, states, people)
  • Edges represent relationships/connections
  • Weighted edges represent cost (distance, time, bandwidth)
  • Used when data has complex many-to-many relationships
When to Use a Graph
  • Network routing and pathfinding
  • Social networks (connections between people)
  • Maps (cities and roads)
  • AI search problems
  • Any problem requiring finding paths between nodes
⚡ GRAPH vs TREE  Tree = hierarchical, one root, no cycles, one path between nodes. Graph = no hierarchy, can have cycles, multiple paths possible, nodes can connect to any other. A tree IS a special case of a graph.
TOPIC 05 · §19.1
Stack, Queue & Linked List ADTs
ALGORITHMS TO FIND · INSERT · DELETE
Stack Algorithms
// PUSH — add to stack (check not full first) IF TopPointer < MaxSize - 1 THEN TopPointer ← TopPointer + 1 Stack[TopPointer] ← Item ENDIF // POP — remove from stack (check not empty first) IF TopPointer >= 0 THEN Item ← Stack[TopPointer] TopPointer ← TopPointer - 1 RETURN Item ENDIF
Queue Algorithms
// ENQUEUE — add to queue (check not full) IF Count < MaxSize THEN Queue[TailPointer] ← Item TailPointer ← (TailPointer + 1) MOD MaxSize // circular wrap Count ← Count + 1 ENDIF // DEQUEUE — remove from queue (check not empty) IF Count > 0 THEN Item ← Queue[HeadPointer] HeadPointer ← (HeadPointer + 1) MOD MaxSize Count ← Count - 1 RETURN Item ENDIF
Linked List Algorithms
// FIND item in linked list Current ← StartNode WHILE Current <> -1 AND Data[Current] <> Target Current ← Pointer[Current] ENDWHILE // If Current = -1, item not found // INSERT at beginning of linked list NewNode ← FreeNode FreeNode ← Pointer[FreeNode] Data[NewNode] ← Item Pointer[NewNode] ← StartNode StartNode ← NewNode // DELETE from linked list // Find node before the one to delete, redirect its pointer Pointer[PreviousNode] ← Pointer[NodeToDelete] Pointer[NodeToDelete] ← FreeNode FreeNode ← NodeToDelete
TOPIC 06 · §19.1
Dictionary ADT
WHAT IT IS · OPERATIONS · IMPLEMENTATION
DICTIONARY ADT
  • Stores key-value pairs
  • Each key is unique
  • Values accessed by their associated key
  • Also called a hash map or associative array
  • Can be implemented from arrays, linked lists or hash tables
Dictionary Operations
  • Create — initialise empty dictionary
  • Add(key, value) — insert new key-value pair
  • Delete(key) — remove a key-value pair
  • Get(key) — retrieve value for given key
  • Contains(key) — check if key exists
  • Update(key, value) — modify existing value
Implementing Dictionary from ADTs
  • From arrays: use parallel arrays (keys[ ] + values[ ])
  • From linked list: each node stores key + value + pointer
  • From hash table: hash key → find storage location
  • Binary tree: keys stored in BST order — O(log n) search
// Dictionary using parallel arrays DECLARE Keys : ARRAY[0:99] OF STRING DECLARE Values : ARRAY[0:99] OF STRING DECLARE Count : INTEGER ← 0 // Add key-value pair PROCEDURE Add(key : STRING, value : STRING) Keys[Count] ← key Values[Count] ← value Count ← Count + 1 ENDPROCEDURE // Get value by key FUNCTION Get(key : STRING) RETURNS STRING FOR i ← 0 TO Count - 1 IF Keys[i] = key THEN RETURN Values[i] NEXT i ENDFUNCTION
TOPIC 07 · §19.1
Big O Notation & Algorithm Comparison
TIME COMPLEXITY · SPACE COMPLEXITY · COMPARING ALGORITHMS
BIG O NOTATION

Used to indicate the time or space complexity of an algorithm — how performance scales with input size n.

ALGORITHMTIME COMPLEXITYMEANING
Linear searchO(n)Time increases linearly with n
Binary searchO(log n)Time increases logarithmically — very efficient
Bubble sortO(n²)Time increases as square of n — slow for large n
Insertion sortO(n²) worst / O(n) bestEfficient for nearly-sorted data
BST find (balanced)O(log n)Same as binary search
Hash table lookupO(1)Constant time — best possible
Comparing Algorithms — Criteria
  • Time taken to complete the task
  • Memory/storage space used
  • Complexity of implementation
  • Performance for different data sizes
  • Best/worst/average case behaviour
Space Complexity
  • Amount of memory an algorithm uses
  • Also expressed in Big O notation
  • e.g. recursive algorithms use O(n) stack space
  • Iterative equivalents often use O(1) space
⚡ BIG O ORDER (best to worst)  O(1) → O(log n) → O(n) → O(n log n) → O(n²) → O(2ⁿ). For exam: Binary search O(log n) is much better than Linear search O(n) for large datasets. Bubble sort O(n²) is slow for large n.

QUESTION 01
Explain what a base case and a general case are in recursion, and why both are necessary. [4]

MARK SCHEME

  • Base case: the stopping condition — when the function does not call itself again (1)

★ CHALLENGE
QUESTION 08
Trace the recursive factorial function for n=4. Show the winding and unwinding phases. [4]

MARK SCHEME

  • Winding: Factorial(4) calls Factorial(3), calls Factorial(2), calls Factorial(1), calls Factorial(0) (1)
  • Base case reached: Factorial(0) returns 1 (1)
  • Unwinding: Factorial(1)=1×1=1, Factorial(2)=2×1=2, Factorial(3)=3×2=6 (1)
  • Factorial(4)=4×6=24 (1)
★ CHALLENGE
QUESTION 09
Explain what the compiler must produce when translating recursive code and why this is necessary. [4]

MARK SCHEME

  • Compiler produces code to push return addresses onto stack with each recursive call (1)
  • Also pushes values of local variables onto stack (1)
  • After base case reached: code to pop return addresses/local variables off stack (1)
  • Necessary because each recursive call needs its own context — stack maintains LIFO order for unwinding (1)
