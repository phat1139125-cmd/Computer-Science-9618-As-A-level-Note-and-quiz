TOPIC 02 · §13.1
Composite Data Types
RECORD · SET
Record
  • Uses other data types to form a single new type
  • Contains related items with fixed number of fields
  • Fields can be primitive or user-defined types
Set
  • Unordered list — ALL elements same data type
  • Theory operations: intersection, union
  • Includes data type in its definition
// Record type TYPE StudentRecord DECLARE StudentID : INTEGER DECLARE Name : STRING DECLARE Grade : CHAR ENDTYPE // Set type TYPE IntSet = SET OF INTEGER DEFINE mySet = (1, 2, 3) : IntSet
⚡ SET vs RECORD  Set = all same type, unordered, supports set operations. Record = different types, ordered named fields, fixed number.
TOPIC 03 · §13.1
Non-Composite Data Types
ENUMERATED · POINTER
Enumerated Type
  • Ordered list of all possible values
  • Values defined by programmer
  • Each value has implicit ordinal position
  • Only one data type in its definition
Pointer Type
  • Stores a memory address/location
  • Indicates the type of data at that address
  • Used in dynamic data structures (linked lists)
  • ^ symbol means "pointer to"
// Enumerated type TYPE Season = (Spring, Summer, Autumn, Winter) TYPE Direction = (North, South, East, West) // Pointer type TYPE IntPointer = ^INTEGER TYPE NodePtr = ^Node

TOPIC 05 · §13.2
File Access Methods & Hashing
SEQUENTIAL ACCESS · DIRECT ACCESS · COLLISIONS
METHODHOW IT WORKSUSED WITH
Sequential AccessRecords read one by one from start until found or EOFSerial and Sequential files
Direct AccessHashing algorithm calculates address — jumps directly to recordSequential (indexed) and Random files
Hashing & Collision Resolution
Hashing Algorithm
  • Mathematical formula applied to key field
  • Result = memory address of record
  • Enables direct access without sequential searching
Collision
  • Two different keys produce same hash value
  • Calculated address already occupied
  • Must be resolved before record can be stored
Resolution — Storing
  • Linear probing: next free space after identified location
  • Overflow area: store in next free overflow space
Resolution — Finding
  • Search overflow area linearly
  • Until matching key found or end of overflow reached
  • If not found → record does not exist
TOPIC 06 · §13.3
Floating-Point Numbers
FORMAT · MANTISSA · EXPONENT · OVERFLOW · UNDERFLOW
FORMAT: M × 2^E

M = mantissa (significant digits → precision). E = exponent (shifts binary point → range). Both in two's complement. Binary point follows sign bit in mantissa.

BIT ALLOCATION CHANGEEFFECT
⬆ More mantissa bitsMore PRECISION / accuracy — more significant digits stored
⬇ Fewer mantissa bitsLess precision — digits truncated
⬆ More exponent bitsGreater RANGE — larger/smaller numbers representable
⬇ Fewer exponent bitsSmaller range of numbers
Overflow
  • Result TOO LARGE to represent
  • Requires more bits than available
  • Digits truncated → precision lost
Underflow
  • Result TOO SMALL (too close to zero)
  • Not enough bits to represent it
  • Digits truncated → precision lost
Why Binary is an Approximation
  • Real numbers have fractional parts
  • Binary limited to powers of 2 fractions
  • Fixed storage → not all fractions stored precisely
Mantissa Bit Weights (Two's Complement)
BIT POSITIONVALUEBIT POSITIONVALUE
Bit 1 (sign)-1Bit 51/16 = 0.0625
Bit 2½ = 0.5Bit 61/32 = 0.03125
Bit 3¼ = 0.25Bit 71/64
Bit 4⅛ = 0.125Bit 81/128
⚡ MANTISSA vs EXPONENT  Mantissa → PRECISION. Exponent → RANGE. Never swap these — it's the most common exam mistake on floating-point questions.
TOPIC 07 · §13.3
Normalisation & Conversions
WHY NORMALISE · FLOAT→DENARY · DENARY→FLOAT
WHY NORMALISE?
  • Store maximum range of numbers in minimum bits
  • Minimises leading 0s/1s — maximises significant bits
  • Increases precision for very small/large numbers
  • Avoids multiple binary representations of same number
  • Normalised: mantissa starts with 01 (positive) or 10 (negative)
Floating-Point Binary → Denary

Convert exponent to denary (two's complement)

Shift mantissa binary point RIGHT by exponent value

Convert result to denary — bits after point = ½, ¼, ⅛...

WORKED EXAMPLE: 01011010 × 00000100

Exponent: 00000100 = 4
Mantissa: 0.1011010 → shift 4 right → 01011.010
= 8 + 2 + 1 + ¼ = 11.25

Denary → Floating-Point Binary

Convert denary to binary with binary point for fractions

Move point LEFT until form 0.1xxx (count moves = exponent)

Express mantissa and exponent in two's complement

WORKED EXAMPLE: Convert 4.75

4.75 = 4 + ½ + ¼ → binary: 0100.11
Shift 3 left → 0.10011 (exponent = 3 = 00000011)
Mantissa: 01001100... Exponent: 00000011

◆ STANDARD
QUESTION 04
Compare serial and sequential file organisation. Give three differences. [6]

MARK SCHEME (any 3 × 2)

  • Serial: stored in chronological order / Sequential: stored ordered by key field (1) — sequential enables faster searching (1)
  • Serial: new records appended to end / Sequential: records inserted in correct key position (1)
  • Serial: every record must be checked when searching / Sequential: searching stops when key field exceeds target value (1)
  • Both require a new file to be created to update records (1)
◆ STANDARD
QUESTION 05
Explain what a collision is in hashing and describe one method of collision resolution. [4]

MARK SCHEME

  • Collision: two different record keys produce the same hash value when passed through the hashing algorithm (1)
  • The calculated storage location is already occupied by another record (1)
  • Resolution: linear probing — store record in next free memory space after the identified location (1)
  • When finding: search overflow area linearly until matching record key found (1)
◆ STANDARD
QUESTION 06
Convert the floating-point binary 01101000 × 00000011 to denary. (8-bit mantissa, 8-bit exponent, two's complement) [3]

MARK SCHEME

  • Exponent: 00000011 = 3 (1)
  • Shift mantissa 3 right: 0.1101000 → 0110.1000 (1)
  • = 4 + 2 + ½ = 6.5 (1)
◆ STANDARD
QUESTION 07
Explain the effect on a floating-point number of: (a) increasing mantissa bits, (b) increasing exponent bits. [4]

MARK SCHEME

  • (a) More mantissa bits → increases precision/accuracy of stored number (1) — more significant digits can be represented (1)
  • (b) More exponent bits → increases the range of numbers that can be represented (1) — larger or smaller numbers can be stored (1)
Examiner: Mantissa = PRECISION. Exponent = RANGE. Never swap. "Makes the number bigger" = 0 marks.
★ CHALLENGE
QUESTION 08
Explain why floating-point binary numbers are stored in normalised form. [3]

MARK SCHEME (any 3)

  • To store the maximum range of numbers in the minimum number of bits (1)
  • Minimises leading 0s/1s — maximises the number of significant bits stored (1)
  • Increases precision/accuracy especially for very small or very large numbers (1)
  • Avoids a number having multiple binary representations (1)
★ CHALLENGE
QUESTION 09
Explain the difference between overflow and underflow in floating-point arithmetic, referring to precision. [4]

MARK SCHEME

  • Overflow: result of operation too large to be represented in available bits (1) — digits truncated, precision lost (1)
  • Underflow: result too small (too close to zero) to be precisely represented (1) — digits truncated, precision lost (1)
