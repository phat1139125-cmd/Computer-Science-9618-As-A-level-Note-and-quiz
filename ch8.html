TOPIC 01 · §8.1
File-based Approach vs Relational Database
DRAWBACKS OF FILE-BASED · ADVANTAGES OF RELATIONAL DB
ISSUEFILE-BASEDRELATIONAL DATABASE
Data redundancyHigh — same data stored many timesReduced — each item stored once (linked tables)
Data consistencyPoor — duplicates stored differentlyMaintained — changes update automatically across tables
Complex queriesHard — new program written each timeEasy — SQL queries run directly
Privacy/accessLack of privacy — no user viewsDifferent views per user — improved privacy
Program-data dependencePrograms must be rewritten if data changesProgram-data independence — data separate from software
⚡ EXAM PATTERN  Advantages of relational DB over file-based: Reduced redundancy / maintained consistency / complex queries / user views / program-data independence. Each = 1 mark with explanation.
TOPIC 02 · §8.1
Database Terminology
ENTITY · FIELD · TUPLE · PRIMARY KEY · FOREIGN KEY · REFERENTIAL INTEGRITY
Entity
  • An object about which data can be stored
  • e.g. Student, Order, Product
  • Represented as a table
Field / Attribute
  • A column in a table
  • Stores one piece of data per record
  • e.g. StudentName, OrderDate
Tuple / Record
  • A single row of data in a table
  • Contains data about one instance of an entity
Primary Key
  • Unique attribute — identifies each record
  • Cannot be null or duplicate
  • Can be used as foreign key in another table
Foreign Key
  • A field in one table that links to a primary key in another
  • Creates relationships between tables
Candidate Key
  • An attribute that could be a primary key
  • Uniquely identifies a record
Secondary Key
  • Alternative/additional key used with primary key to locate data
  • Candidate key not chosen as primary key
Referential Integrity
  • Ensures every foreign key has a corresponding primary key
  • Prevents records being added/deleted incorrectly
  • Ensures changes reflected across all related records
  • Ensures queries return accurate/complete results
TOPIC 03 · §8.1
Normalisation
1NF · 2NF · 3NF · HOW TO NORMALISE
NORMAL FORMRULEHOW TO ACHIEVE
1NFNo repeating groups. All fields atomic.Remove repeating groups. Split composite fields (e.g. Name → FirstName + LastName). Identify primary key.
2NFIn 1NF + no partial key dependencies (all attributes fully dependent on WHOLE primary key)Remove any partial key dependencies. Applies to composite primary keys only.
3NFIn 2NF + no transitive dependencies (all attributes depend only on primary key, not on other non-key attributes)Remove non-key dependencies. Each attribute must depend on primary key AND NOTHING ELSE.
0NF → 1NF
  • Remove/identify repeating groups
  • Ensure each field is atomic
  • Identify primary key
1NF → 2NF
  • Remove partial key dependencies
  • If attribute depends on PART of composite PK → move to separate table
2NF → 3NF
  • Remove transitive/non-key dependencies
  • If attribute depends on another non-key attribute → move to separate table
⚡ 3NF DEFINITION  "All attributes/fields are fully dependent on the primary key AND NO OTHER ATTRIBUTES." This exact phrasing = exam mark.
TOPIC 04 · §8.2
Database Management System (DBMS)
DATA DICTIONARY · LOGICAL SCHEMA · SECURITY · SOFTWARE TOOLS
Data Dictionary Contents
  • Table name / field name
  • Data types for each field
  • Validation rules used
  • Primary and foreign keys
  • Relationships between elements
Logical Schema
  • Shows structure of database and relationships
  • e.g. E-R (Entity-Relationship) diagram
  • Independent of any particular DBMS
  • Describes relationship between data and its structure
DBMS Security Features
  • Authentication — usernames/passwords
  • Backup/recovery procedures — automatic copies
  • Access rights — read/write per user/table
  • Views — users see only required data
  • Encryption — data turned to ciphertext
  • Record and table locking — prevents simultaneous access
DBMS Software Tools
  • Developer interface — create tables, forms, reports
  • Query processor — processes and executes SQL queries
  • Allows user to enter criteria and search data
  • Organises and displays results
TOPIC 05 · §8.3
SQL — DDL & DML
CREATE · ALTER · SELECT · INSERT · UPDATE · DELETE
DDL — Data Definition Language
-- Create a database CREATE DATABASE database_name; -- Create a table CREATE TABLE table_name ( column1 DATATYPE, column2 DATATYPE NOT NULL, PRIMARY KEY(column1), FOREIGN KEY(column2) REFERENCES other_table(column2) ); -- Alter a table ALTER TABLE table_name ADD column_name DATATYPE; DROP COLUMN column_name; RENAME COLUMN old_name TO new_name;
DML — Data Manipulation Language
-- SELECT query SELECT column1, column2 FROM table_name WHERE condition ORDER BY column1 ASC/DESC GROUP BY column1 INNER JOIN other_table ON table1.key = other_table.key; -- Aggregate functions SELECT COUNT(*), SUM(column), AVG(column) FROM table_name; -- Insert, Update, Delete INSERT INTO table_name VALUES (val1, val2); UPDATE table_name SET column1 = value WHERE condition; DELETE FROM table_name WHERE condition;
SQL Data Types
  • CHARACTER — single character
  • VARCHAR(n) — string up to n characters
  • BOOLEAN
  • INTEGER
  • REAL — decimal number
  • DATE
  • TIME
Key SQL Clauses
  • WHERE — filter rows by condition
  • ORDER BY — sort results
  • GROUP BY — group rows with same value
  • INNER JOIN — combine rows from two tables where condition met
  • HAVING — filter groups (use with GROUP BY)
⚡ SQL EXAM TIPS  Always end DDL statements with semicolon. INNER JOIN: ON specifies the linking columns. WHERE filters rows BEFORE grouping; HAVING filters AFTER grouping. VARCHAR(255) allows up to 255 characters.

QUESTION 02
State two advantages of using a relational database over a file-based approach. [4]

MARK SCHEME (any 2 × 2)

  • Reduced data redundancy (1) — each data item stored only once in linked tables (1)
  • Better data consistency (1) — changes in one table update automatically in related tables (1)
  • Complex queries easier (1) — SQL can query multiple linked tables (1)
  • Different views per user (1) — improved privacy, users only see relevant data (1)
◆ STANDARD
QUESTION 03
Explain what is meant by third normal form (3NF). [2]

MARK SCHEME

  • In 2NF with no transitive dependencies (1)
  • All attributes are fully dependent on the primary key AND NO OTHER non-key attributes (1)
Examiner: Both parts needed. "No transitive dependencies" alone = 1 mark. Must also state relationship to primary key.
◆ STANDARD
QUESTION 04
Write an SQL statement to select the StudentName and Grade from a table called Results, where the Grade is greater than 70, ordered by Grade descending. [4]

MARK SCHEME

  • SELECT StudentName, Grade (1)
  • FROM Results (1)
  • WHERE Grade > 70 (1)
  • ORDER BY Grade DESC; (1)
Examiner: Each clause = 1 mark. Capitalization of keywords preferred but not required. Semicolon at end is good practice.
◆ STANDARD
QUESTION 05
Explain the importance of referential integrity in a relational database. [3]

MARK SCHEME (any 3)

  • Ensures every foreign key has a corresponding primary key in the related table (1)
  • Prevents records being added, modified or deleted incorrectly (1)
  • Ensures changes in one table are reflected in all related records (1)
  • Ensures queries return accurate and complete results (1)
  • Prevents non-existent data from being referenced (1)

QUESTION 07
Describe four security features provided by a DBMS. [4]

MARK SCHEME (any 4)

  • Authentication — usernames/passwords to verify user identity (1)
  • Access rights — different users have read/write permissions to different tables (1)
  • Encryption — data stored as ciphertext, cannot be understood without key (1)
  • Backup/recovery — automatic copies created regularly, data can be restored if lost (1)
  • Views — users can only see parts of database relevant to them (1)
  • Record/table locking — prevents simultaneous conflicting access (1)
★ CHALLENGE
QUESTION 08
Write an SQL query to join a Students table and a Courses table, showing StudentName and CourseName where the StudentID matches, for students in Year 12. [5]

MARK SCHEME

  • SELECT Students.StudentName, Courses.CourseName (1)
  • FROM Students (1)
  • INNER JOIN Courses ON Students.StudentID = Courses.StudentID (1)
  • WHERE Students.Year = 12; (1)
