TOPIC 01 · §11.1
Good Programming Practice
READABILITY · CONSTANTS · MEANINGFUL NAMES
Features Making Code Understandable
  • Indentation — shows structure/nesting clearly
  • White space — separates logical sections
  • Comments — explains purpose of code sections
  • Meaningful variable names (e.g. camelCase)
  • Capitalised keywords
  • Standard way to indicate special cases
Importance of Good Practice
  • Easier to understand — describes purpose of identifiers
  • Easier to debug, test and maintain
  • Others can understand and modify the code
Constants
  • Used for values that don't change during execution
  • Avoids input error or accidental change
  • Easier to maintain — change value in one place only
  • Makes program easier to understand
// Good practice examples CONSTANT MAX_SIZE : 100 // Use constant not magic number DECLARE studentCount : INTEGER // Meaningful name DECLARE isFound : BOOLEAN // Clear boolean name // Poor practice (avoid) DECLARE x : INTEGER // Meaningless name DECLARE n : INTEGER // Meaningless name
⚡ EXAM  When asked "state two features of good programming practice" — indentation + meaningful variable names are always safe marks. When asked WHY: "makes code easier to maintain and debug by other programmers."
TOPIC 02 · §11.2
Selection Constructs
IF STATEMENT · CASE STATEMENT
// IF statement (with optional ELSE) IF score >= 70 THEN OUTPUT "Pass" ELSE IF score >= 50 THEN OUTPUT "Merit" ELSE OUTPUT "Fail" ENDIF // CASE statement CASE OF grade 'A' : OUTPUT "Excellent" 'B' : OUTPUT "Good" 'C' : OUTPUT "Average" OTHERWISE : OUTPUT "Below average" ENDCASE
CASE Statement Properties
  • Clauses checked in sequence
  • If first clause satisfied — others NOT tested
  • OTHERWISE clause may never execute if all values covered
  • Use instead of many ELSE IF chains

FOR · WHILE · REPEAT · WHEN TO USE EACH

TOPIC 04 · §11.3
Procedures & Functions
DEFINITION · DIFFERENCE · PARAMETERS · INTERFACE
KEY DIFFERENCE

Function: returns a value. Used in an expression — the return value replaces the call.
Procedure: does NOT return a value. Can output values. Called with CALL statement.

// PROCEDURE definition PROCEDURE DisplayGreeting(name : STRING) OUTPUT "Hello, ", name ENDPROCEDURE // PROCEDURE call CALL DisplayGreeting("Ahmed") // FUNCTION definition FUNCTION Square(n : INTEGER) RETURNS INTEGER RETURN n * n ENDFUNCTION // FUNCTION call (used in expression) result ← Square(5) // result = 25
Benefits of Using Procedures/Functions
  • Can be called repeatedly when required
  • Only designed and tested once
  • Changes to code only needed in one place (easier to maintain)
  • Reduces complexity of program
  • Easier to test and debug
Function/Procedure Interface
  • Refers to the parameters and return value
  • Defines parameter names, data types and order
  • Provides mechanism to pass data between modules
TOPIC 05 · §11.3
Pass by Value vs Pass by Reference
BYVAL · BYREF · WHEN TO USE EACH
FEATUREPASS BY VALUE (BYVAL)PASS BY REFERENCE (BYREF)
What is passedA COPY of the variable's valueThe memory ADDRESS of the variable
Changes in moduleDo NOT affect original variableDO affect original variable permanently
SafetySafer — original protectedLess safe — original can be changed
Use whenYou only need to READ the valueYou need to MODIFY and return the value
// Pass by VALUE — copy passed, original unchanged PROCEDURE Double(BYVAL num : INTEGER) num ← num * 2 // only changes local copy ENDPROCEDURE // Pass by REFERENCE — original variable modified PROCEDURE Double(BYREF num : INTEGER) num ← num * 2 // changes original variable ENDPROCEDURE
⚡ BYVAL vs BYREF EXAM  BYVAL = copy passed = original unchanged. BYREF = address passed = original IS changed. Use BYREF when procedure needs to return multiple values (since a function only returns one).
TOPIC 06 · §11.1
Library Routines
WHAT THEY ARE · BENEFITS · WHEN TO USE
LIBRARY ROUTINES

Pre-written, pre-tested functions and subroutines that can be imported and called in your own program. More complex functions available through program libraries.

Benefits During Development
  • Already tried and tested — free from errors
  • Perform functions you may not be able to program
  • Readily available — speed up development
  • Used for tasks repeated in several places
When to Use
  • Task performed/repeated in several places in code
  • Part of algorithm performs a specific, reusable task
  • Reduces complexity of main program
  • When testing/debugging is easier with modular code

QUESTION 02
State the difference between a function and a procedure. [2]

MARK SCHEME

  • A function returns a value / a procedure does not return a value (1)
  • A function is used in an expression — the return value replaces the call (1)
Examiner: The key mark is "returns a value" for function vs "does not return a value" for procedure. A procedure can still output values using OUTPUT — that's not the same as returning.
◆ STANDARD
QUESTION 03
Explain the difference between passing a parameter by value and passing by reference. [4]

MARK SCHEME

  • By value: a copy of the variable's value is passed to the module (1)
  • By value: changes made inside the module do NOT affect the original variable (1)
  • By reference: the memory address of the variable is passed (1)
  • By reference: changes made inside the module DO permanently change the original variable (1)

QUESTION 04
Write a function in pseudocode called FindMax that takes two integer parameters and returns the larger value. [4]

MARK SCHEME

  • FUNCTION FindMax(a : INTEGER, b : INTEGER) RETURNS INTEGER (1)
  • IF a > b THEN (1)
  • RETURN a (1)
  • ELSE / RETURN b / ENDIF / ENDFUNCTION (1)
◆ STANDARD
QUESTION 05
Justify which loop structure (FOR, WHILE, or REPEAT) is most appropriate for each scenario: (a) Validate user input must be between 1 and 10. (b) Process exactly 50 records from a file. [4]

MARK SCHEME

  • (a) REPEAT loop (1) — input must be requested at least once before checking if valid; condition checked after body executes (1)
  • (b) FOR loop (1) — number of iterations (50) is known in advance; count-controlled (1)
★ CHALLENGE
QUESTION 06
Write a procedure in pseudocode that takes an array of 10 integers by reference and replaces any negative values with 0. [5]

MARK SCHEME

  • PROCEDURE FixNegatives(BYREF nums : ARRAY[1:10] OF INTEGER) (1)
  • FOR i ← 1 TO 10 (1)
  • IF nums[i] < 0 THEN (1)
  • nums[i] ← 0 (1)
  • ENDIF / NEXT i / ENDPROCEDURE (1)
Examiner: Must use BYREF since we're modifying the original array. BYVAL would only modify a local copy.

  • Only designed and tested once — reduces development time (1)
  • Changes only need to be made in one place — easier to maintain (1)
  • Reduces complexity of main program — easier to read and understand (1)
