TOPIC 01 · §14.1
Protocols & Their Purpose
WHY PROTOCOLS ARE ESSENTIAL · SSL/TLS
PURPOSE OF PROTOCOLS
  • Provide a standard set of rules to enable successful data transfer
  • Enable communication/compatibility between devices from different manufacturers
  • Make communications independent of software and hardware
  • Without protocols: devices with different protocols cannot communicate
SSL — Secure Socket Layer
  • Encrypts data transferred over internet
  • Decides which encryption algorithms to use
  • Performs data integrity checks and compression
TLS — Transport Layer Security
  • More effective than SSL
  • Provides encryption, authentication and data integrity
  • Prevents third-party eavesdropping
  • Ensures privacy between communicating devices
⚡ EXAM  "Why is a protocol essential for communication?" → standard rules enable devices from different manufacturers/platforms to communicate. Without common rules, data cannot be interpreted correctly.
TOPIC 02 · §14.1
TCP/IP Protocol Suite
4 LAYERS · PURPOSE OF EACH LAYER · INTERACTIONS
TCP/IP — KEY FACTS
  • Maintains connection between two hosts — ensures successful delivery
  • Represented as a stack — each layer has separate functionality
  • Separate layers make hardware and software compatibility easier
  • Each layer can only accept input from adjacent layers only
4 · Application Layer
  • Interacts directly with user/applications
  • Used by web browsers and server software
  • Defines protocols for data exchange
  • Provides access to services in lower layers
3 · Transport Layer
  • Breaks data into manageable packets (segmentation)
  • Adds packet header + sequence number
  • Controls flow of packets
  • Handles packet loss/corruption — ensures error-free delivery
2 · Internet Layer
  • Identifies intended network and host
  • Routes packets independently via optimum route
  • Addresses packets with source/destination IP
  • Uses IP address + port number to form a socket
1 · Link Layer
  • Handles how data is physically sent
  • Ensures correct network protocols followed
  • Formats data into frames for transmission
  • Maps IP addresses to MAC addresses

⚡ LAYER INTERACTIONS  Each layer ONLY communicates with adjacent layers (one above or one below). User interaction at Application layer. Hardware access at Link layer. Data encapsulated as it moves down, de-encapsulated going up.

Application Layer Protocols
HTTP · FTP · SMTP · POP3/IMAP · BITTORRENT
PROTOCOLPURPOSEKEY DETAIL
HTTPS/HTTPTransfer of web pages and hypertext documentsUsed by web browsers; HTTPS = encrypted
FTPSend and receive files over a network between devicesTransfer from server to client on network
SMTPSending/uploading emailsPUSH protocol — sends email out

TOPIC 04 · §14.2
Circuit Switching
HOW IT WORKS · ADVANTAGES · DISADVANTAGES · USE CASES
CIRCUIT SWITCHING
  • Data transferred using a dedicated circuit/channel
  • Circuit established BEFORE transmission starts
  • Circuit lasts for entire duration — closed after transmission ends
  • All data transferred over the same route
  • Entire bandwidth available for the connection
  • Implemented at the physical layer
✅ Advantages
  • No need to reassemble data — arrives in order
  • Entire bandwidth available throughout
  • Simple and fast — fixed data rate, same path
  • Fast data transfer — suitable for real-time
❌ Disadvantages
  • No other transmission possible when in use — wasted bandwidth
  • Less secure — all data travels same route (easier to intercept)
  • Cost/time to establish dedicated connection
  • Only one route — if error occurs, transmission ends
  • Setup time before transmission can begin
  • Circuit always active even when idle
📌 Use When
  • Dedicated path needed throughout (phone calls)
  • Whole bandwidth required
  • Real-time communication (voice, video streaming)
  • Long continuous communication
TOPIC 05 · §14.2
Packet Switching
HOW IT WORKS · PACKET STRUCTURE · ADVANTAGES · DISADVANTAGES
PACKET SWITCHING
  • Data divided into equal-sized packets (header + payload + trailer)
  • Each packet dispatched independently — can take different routes
  • Routes determined by routing table — optimum route always taken
  • Packets may arrive out of order — reassembled using sequence numbers
  • Missing/corrupted packets → resend request sent
  • Implemented at the network layer
PACKET HEADER CONTAINS

Source IP address, destination IP address, packet number/sequence number, other routing information

✅ Advantages
  • Packets rerouted/retransmitted if error — more likely to arrive
  • Bandwidth shared — packets from multiple messages share paths
  • More secure — packets travel different routes
  • High data transmission rate possible
❌ Disadvantages
  • Time delay — reassembly, shared bandwidth, potential resends
  • Requires complex algorithms
  • Needs lots of RAM to handle large data amounts
  • Unsuitable for real-time transmission
📌 Use When
  • Sending large files not needing live streaming
  • Must overcome faulty lines via rerouting
  • Secure communication needed
  • Entire bandwidth not required
  • e.g. emails, documents, text messages

TOPIC 06 · §14.2
Router in Packet Switching
FUNCTION · ROUTING TABLE · BENEFITS OF PACKET SWITCHING
Router Function
  • Examines packet header — reads destination IP address
  • Accesses routing table — contains netmask, gateway, available hops, route status
  • Decides next hop/best route
  • Forwards packet to next hop
Benefits of Packet Switching
  • Accuracy — ensures accurate delivery
  • Completeness — missing packets detected, resend request sent
  • Rerouting — detects network changes, sends data alternate way
  • Simultaneous use — multiple users share channel
  • Better security — packets hashed, travel different routes
Drawbacks
  • Time delays — correcting packet errors
  • Complex protocols required
  • Unsuitable for real-time applications

Distinguish between POP3 and IMAP email protocols. [2]

MARK SCHEME

  • POP3: downloads emails from server and deletes them from server (1)
  • IMAP: downloads emails but keeps originals on server — keeps client and server in sync (1)

QUESTION 04
Describe how data is transmitted using packet switching across the internet. [5]

MARK SCHEME (any 5)

  • Data divided into equal-sized packets (1)
  • Each packet has a header containing source/destination IP and sequence number (1)
  • Packets dispatched independently — can take different routes (1)
  • Routes determined by routing table — optimum route taken (1)
  • Packets may arrive out of order — reassembled using sequence numbers at destination (1)

◆ STANDARD
QUESTION 05
Compare circuit switching and packet switching. Give four differences. [8]

MARK SCHEME (any 4 × 2)

  • Circuit: dedicated route throughout / Packet: packets take independent routes (1) — packet more resilient to failures (1)
  • Circuit: bandwidth not shared / Packet: bandwidth shared between users (1) — packet more efficient use of bandwidth (1)
  • Circuit: data arrives in order / Packet: arrives out of order, reassembled using sequence numbers (1)
  • Circuit: suitable for real-time / Packet: not suitable for real-time — time delays (1)
  • Circuit: less secure (single route) / Packet: more secure (multiple routes) (1)
◆ STANDARD
QUESTION 06
Explain the role of a router in packet switching. [4]

MARK SCHEME

  • Examines packet header and reads the destination IP address (1)
  • Accesses its routing table containing information about available routes (1)
  • Decides the next hop/best route for the packet (1)
  • Forwards the packet to the next router/destination (1)
★ CHALLENGE
QUESTION 07
A company needs to transmit live video calls between offices and also send large reports to clients by email.
Justify which switching method is appropriate for each use case. [4]

MARK SCHEME

  • Live video: circuit switching (1) — requires dedicated path and entire bandwidth for real-time, uninterrupted transmission (1)
  • Email reports: packet switching (1) — large files divided into packets, bandwidth shared, delivery not time-critical (1)
★ CHALLENGE
QUESTION 08
Explain how TCP/IP layers interact and why this layered approach is beneficial. [4]

MARK SCHEME

  • Each layer can only accept input from adjacent layer (next higher or lower) (1)
  • There is an interface between adjacent layers — interactions via installed software (1)
  • Benefit: separate layers make hardware and software compatibility easier to implement (1)
  • Benefit: each layer is self-contained — changes to one layer don't affect others (1)
