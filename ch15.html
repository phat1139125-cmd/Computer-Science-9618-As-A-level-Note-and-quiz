Interrupt Handling (both RISC and CISC)

Processor detects interrupt at start/end of F-E cycle

Current program stopped — register contents stored on a stack

Appropriate ISR called and executed

After ISR: registers restored from stack — program resumes

RISC interrupt extra complexity:  Instructions still in pipeline when interrupt received — all discarded except the last. ISR applied to remaining instruction. Processor restarts with next instruction after servicing.
⚡ RISC EXAM MNEMONICS  RISC = Few instructions, Fixed length, Many registers, Hard-wired, Software-emphasis, RAM-heavy, Pipelining. CISC = Many instructions, Variable length, Few registers, Programmable, Hardware-emphasis, Cache-heavy.
TOPIC 02 · §15.1
Pipelining
HOW IT WORKS · STAGES · PURPOSE
PIPELINING

Allows several instructions to be processed simultaneously — increases instruction throughput during F-E cycle. While one instruction is being executed, the next can be fetched.

Pipeline Stages (each takes one clock cycle)
Stage 1
  • Instruction Fetch (IF)
Stage 2
  • Instruction Decode (ID)
Stage 3
  • Operand Fetch (OF)
Stage 4
  • Execute (EX)
Stage 5
  • Result Store (WB)
HOW PIPELINING WORKS

No two instructions can execute the same stage at the same clock cycle. Instruction 2 begins at clock cycle 2 while instruction 1 has moved to stage 2, etc. Overlapping stages increases throughput.

⚡ PIPELINING EXAM  "While one instruction is being executed, the next instruction can be fetched." This is the core statement. RISC is designed for pipelining because all instructions are the same length (predictable decode time).

TOPIC 04 · §15.1
Virtual Machines
DEFINITION · BENEFITS · LIMITATIONS · HOST/GUEST OS
VIRTUAL MACHINE

An emulation of a computer system (hardware and software) using a host computer system. Uses a guest operating system for emulation.

✅ Benefits
  • Cost saving — test new systems without buying hardware
  • Different instruction set architectures emulated on one computer
  • VM crash doesn't affect host machine
  • Security — virus only affects VM, not host
  • Multiple VMs can co-exist on one computer
  • Emulate programs incompatible with host OS
  • Run old software on newer systems
❌ Limitations
  • Cannot emulate hardware developed after VM was created
  • Extra code executed — less efficient, slower, uses more RAM
  • Higher maintenance — both host and VM must be maintained
  • VM affected by weaknesses of host machine

TOPIC 05 · §15.2
Half-Adder & Full-Adder
COMBINATIONAL CIRCUITS · TRUTH TABLES · GATE COMPOSITION
Half-Adder
  • Performs binary addition on 2 bits
  • 2 inputs (X, Y) → 2 outputs (Sum, Carry)
  • Sum = X XOR Y
  • Carry = X AND Y
  • Gates: XOR + AND
Full-Adder
  • Two half-adders combined + OR gate
  • 3 inputs (X, Y, Cin) → 2 outputs (Sum, Cout)
  • Handles carry-in from previous bit
  • Used for multi-bit binary addition

TOPIC 06 · §15.2
SR & JK Flip-Flops
SEQUENTIAL CIRCUITS · STORAGE · TRUTH TABLES
SEQUENTIAL CIRCUITS

Output depends on input value produced from a previous output value. Output depends on history — has memory.

SR Flip-Flop
  • Stores one bit of data (0 or 1)
  • Used in RAM — each flip-flop = one storage cell
  • Inputs: S (Set), R (Reset)
  • Outputs: Q and NOT Q
  • Made of 2 cross-coupled NOR or NAND gates
SR Problems
  • Invalid state possible (NOR: S=1,R=1 / NAND: S=0,R=0)
  • Circuit unstable if inputs don't arrive simultaneously
  • Q and NOT Q become equal in invalid state
JK Flip-Flop (improved SR)
  • Eliminates invalid input combinations
  • Used in shift registers and binary counters
  • Uses clock pulse to synchronise inputs
  • J=0, K=0 → no change
  • J=1, K=1 → Q TOGGLES each clock pulse
  • Q always equals J; NOT Q always equals K

TOPIC 07 · §15.2
Boolean Algebra & Karnaugh Maps
NOTATION · DE MORGAN'S LAWS · K-MAP SIMPLIFICATION
Boolean Notation
GATENOTATIONEXAMPLE
ANDA · BA AND B = A.B
ORA + BA OR B = A+B
NOTĀ (A-bar)NOT A = Ā
NANDĀ·B̄ (overline AB)NOT(A AND B)
NORĀ+B̄ (overline A+B)NOT(A OR B)
De Morgan's Laws
Law 1
  • NOT(A AND B) = NOT A OR NOT B
  • Ā·B̄ = Ā + B̄
  • NAND = NOT A OR NOT B
Law 2
  • NOT(A OR B) = NOT A AND NOT B
  • Ā+B̄ = Ā · B̄
  • NOR = NOT A AND NOT B
Karnaugh Maps (K-Maps)
PURPOSE OF K-MAPS
  • Method of simplifying Boolean expressions from a truth table
  • Minimises number of Boolean expressions and logic gates
  • Provides a more efficient circuit
K-Map Rules
  • Group adjacent cells containing 1s
  • Groups cannot be diagonal — CAN wrap around edges
  • Only 2ⁿ cells per group (2, 4, 8...)
  • Each 1 must be in at least one group
  • Overlapping groups allowed
  • Groups should be as LARGE as possible
  • Use FEWEST groups possible
Reading K-Map Output
  • Each group gives one simplified term
  • Variables that don't change within group are kept
  • Variables that change are eliminated
  • Final expression = OR of all group terms
⚡ K-MAP EXAM TIPS  Always make groups as large as possible — larger groups = fewer variables = simpler expression. Groups CAN wrap around the edges of the map. Priority: 8s → 4s → 2s → 1s. Never diagonal groups.
