THEORY — SECURITY & ENCRYPTION
TOPIC 01 · §17.1
Key Cryptography Concepts
PURPOSE · NON-REPUDIATION · KEY TYPES
PURPOSE OF KEY CRYPTOGRAPHY
  • Ensures message is authentic — from a trusted source
  • Ensures message has not been altered during transmission
  • Makes sure only intended receiver can understand message
  • Non-repudiation: neither sender nor receiver can deny the transmission happened
Public Key
  • Available to everyone — freely distributed
  • Used to ENCRYPT data sent TO the key owner
  • Cannot decrypt what it encrypts
Private Key
  • Unpublished/secret — never transmitted anywhere
  • Has a matching public key
  • Used to DECRYPT data encrypted with matching public key
  • Also used to CREATE digital signatures
TOPIC 02 · §17.1
Asymmetric Encryption
TWO KEYS · PROCESS · DETECTING ALTERATIONS
ASYMMETRIC ENCRYPTION
  • Uses a pair of different keys — public + private
  • One key encrypts, the matching key decrypts
  • Only public key available to everyone — private key stays secret
  • Longer process — more complex
  • Key length: usually 2048 bits
Sending a Private Message (Encryption Process)

Receiver's computer generates a matching key pair (public + private)

Receiver sends their public key to the sender

Sender encrypts data using receiver's public key → creates cipher text

Cipher text sent to receiver — can only be decrypted using receiver's private key

Detecting Message Alterations (Digital Signature)

Message decrypted using receiver's private key

Digital signature decrypted using sender's public key → recovers original digest

Received message hashed with agreed hashing algorithm → produces second digest

Two digests compared — if same, message not altered; if different, message was tampered

⚡ ASYMMETRIC KEY RULE  Encrypt with PUBLIC key → decrypt with PRIVATE key. Sign with PRIVATE key → verify with PUBLIC key. Public key = freely shared. Private key = NEVER shared.
TOPIC 03 · §17.1
Symmetric Encryption
SINGLE KEY · COMPARISON WITH ASYMMETRIC
SYMMETRIC ENCRYPTION
  • Uses a single key shared by all parties
  • Same key used to encrypt AND decrypt
  • Simple and fast process
  • Higher risk of compromise — key must be shared securely
  • Key length: usually 128 or 256 bits

TOPIC 04 · §17.1
Quantum Cryptography
HOW IT WORKS · BENEFITS · LIMITATIONS
QUANTUM CRYPTOGRAPHY
  • Protects security of data transmitted over fibre optic cable
  • Uses quantum properties of photons to transmit encryption keys
  • Virtually unhackable — any eavesdropping changes photon properties
✅ Benefits
  • Detects any eavesdropping — photon properties change if intercepted
  • Once transferred, key integrity guaranteed — cannot be copied or decrypted later
  • More secure, longer keys can be used
❌ Limitations
  • Limited range — only short distances
  • Requires dedicated fibre-optic line + specialist hardware — expensive
  • Polarisation of light may be altered during transmission
  • Still new — lacks vital features, high error rates
  • No digital signatures, certified mail etc. yet
TOPIC 05 · §17.1
SSL/TLS Protocols
PURPOSE · USE CASES · CLIENT-SERVER HANDSHAKE
SSL — Secure Socket Layer
  • Encrypts data transferred over internet
  • Decides which encryption algorithms to use
  • Data integrity checks and compression
TLS — Transport Layer Security
  • More effective than SSL
  • Provides encryption + authentication + data integrity
  • Prevents third-party eavesdropping
Where SSL/TLS is Used
  • Online banking and financial transactions
  • Sending/receiving emails
  • Cloud storage facilities
  • VPN connections
  • Any HTTPS website
SSL/TLS Handshake Process

Application initiates SSL/TLS connection — becomes the client; receiving application becomes server

Every new session begins with a handshake

Digital certificate requested/sent from client/server

Client verifies server's digital certificate and obtains server's public key

Encryption algorithms agreed by server and client

Symmetric session keys generated for the session

TOPIC 06 · §17.1
Digital Certificates & Digital Signatures
CERTIFICATE AUTHORITY · HOW SIGNATURES WORK
DIGITAL CERTIFICATE
  • Electronic/online document used to authenticate identity of website/individual/organisation
  • Typically issued by a Certificate Authority (CA)
  • Contains: identifying information + owner's public key
  • Provides public key for validating the private key associated with signature
How a Digital Certificate is Acquired

Enquirer sends public key + proof of identity to Certificate Authority (CA)

CA verifies the enquirer's details and identity

If verified, CA creates and issues certificate containing enquirer's public key

Data encrypted with CA's public key; sent using CA's private key

How a Digital Signature is Created & Verified
Creating the Signature (Sender)
  • Message passed through hashing algorithm → produces digest
  • Digest encrypted with sender's PRIVATE key → forms the signature
  • Message + signature sent to receiver
Verifying the Signature (Receiver)
  • Receiver decrypts signature using sender's PUBLIC key → recovers original digest
  • Receiver hashes the received message → produces second digest
  • Two digests compared — if same, message authentic and unaltered
⚡ DIGITAL SIGNATURE PROCESS  Sign = hash message → encrypt digest with PRIVATE key. Verify = decrypt signature with PUBLIC key → hash received message → compare digests. If digests match = authentic + unaltered.
